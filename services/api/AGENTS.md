# 后端补充约定

适用于此目录，结合 [根约定](../../AGENTS.md)。相关依据：[计划](../../docs/PLAN.md)、[UX](../../docs/UX.md) 中认证、同步、发送与通知章节。

## 实现边界

采用 Node.js ESM、Fastify 和 better-sqlite3 / SQLite 单体服务；容器使用 Node.js 24，精确依赖见 package-lock.json。接口、迁移与可恢复持久状态优先，不无故引入中间件。不能把服务端测试当成真机闭环完成；当前验收证据见 ../../docs/P1-ACCEPTANCE.md。按 modules/auth、devices、inbox 划分业务，routes 不直接操作 SQL，service 拥有功能事务，platform 不反向依赖业务模块。详见 docs/ARCHITECTURE.md。

## 认证与数据

- 私有 HTTP 和实时接口均验证身份与资源归属；客户端隐藏界面不构成授权。
- 持久 PWA 会话可撤销、跨普通后端重启保存，与 Android 配对凭证隔离。Cookie 和 CSRF 策略遵循 UX 规格，不把长期凭证放入 URL 或前端可读存储。
- 续期不能复活已撤销会话。配对令牌短期、单次、原子消费并限制尝试；不把永久凭证编码进二维码。
- 通知凭证仅服务端保存，日志脱敏；无公开注册。数据保留、删除与备份范围必须明确，默认不删除手机原短信。

## 同步、命令和通知

- 收件以设备事件 ID 幂等入库，持久化后 ACK，区分原接收时间和同步时间。
- 发件命令固定目标 SIM、幂等键、有效期；领取/取消/过期使用原子状态条件，处理重连及并发。
- 不把领取、API 返回成功或连接成功当作短信发出；结果未知或部分分段成功不自动整条重发。
- 收件与通知投递解耦，持久记录通知尝试；通知失败不回滚短信。补传旧短信时按时效抑制过时提醒。
- 变更协议时检查旧版 Android，使用显式版本/能力和兼容迁移，不要求所有端同时上线。

## 验证

本目录使用 `npm ci`、`npm test`、`npm start`；部署使用 `docker compose up -d --build --wait`；同一镜像托管 PWA，HTTPS 由主机已有代理负责，不在 Compose 提供代理或发布 80/443。`npm run test:compose` 使用独立项目和虚构数据验证容器重建持久化，结束仅删除自己的测试卷。初始化管理员、配置、迁移与备份见 [README](README.md)，接口语义见 [API v1](../../docs/API-V1.md)。不得将测试清理命令作用于用户部署的数据卷。

行为变更按需覆盖：未授权读取、会话续期/撤销并发、配对码重用、重复事件、重复发件请求、领取/取消竞争、命令过期、数据库迁移和通知失败。外部短信与通知测试默认使用 mock，不产生真实发送副作用。仅当任务明确包含真实联调时使用指定测试环境。
