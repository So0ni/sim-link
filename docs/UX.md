# SIMLink UX 规格

版本：讨论稿 v0.2 · 2026-09-28。此文档定义流程、页面与状态；已生成 PWA 和 Android 视觉方向稿；PWA 收件箱交互原型已位于 `apps/web/`，使用虚构数据，尚未接入真实认证、后端或 Android。

## 核心体验

打开就能找到新短信；发送前明确知道使用哪张卡；遇到异常知道是网页、服务器、手机还是 SIM 出了问题。

手机优先，PWA 日常使用；Android 主要用于安装、配对、权限修复及运行状态。简体中文优先，结构预留英文。视觉以清晰列表、易读正文、稳定导航为目标，配色与具体组件待视觉探索确定。

## 信息架构

| 一级入口 | 主要内容 | 默认动作 |
| --- | --- | --- |
| 短信 | 全部/未读、SIM 筛选、会话、详情 | 新建短信、复制验证码、回复 |
| 来电 | 来电事件及记录；按已验证能力开放 | 查看详情、复制号码 |
| 设备 | Android 节点、每张 SIM、连接与权限 | 添加设备、诊断、修复 |
| 设置 | 通知、会话安全、数据保留、服务器信息 | 配置渠道、管理登录设备 |

首期只有短信能力时为三个入口；来电模块可用后增至四个。通知位于设置内，设备异常也可直接链接到相关设置。

移动端底部导航，详情独立页面；桌面端左侧导航，短信页使用会话列表和详情双栏。同一发件人的不同 SIM 会话分开，避免回复用错卡。

## 流程 A：首次接入

1. 部署者打开 HTTPS 站点，以部署时一次性凭证创建管理员；没有设备时显示“连接你的第一台 Android”。
2. PWA 添加设备页明确“需要 Android 14 或更新版本”，展示 APK 安装说明、实测兼容列表、一次性二维码、有效期和手动配对方式。Android 版本达到要求与具体机型已验证分开表述。
3. Android 欢迎页提供“扫描配对二维码”和“手动输入服务器地址”。摄像头权限仅在扫码时请求。
4. 扫码解析后展示服务器地址；用户确认连接。手动路径依次输入地址、测试连接、输入配对码。
5. 连接检查拆分为地址可达、TLS 有效、API 兼容；出错保留已填内容，给出可操作的修复文案。
6. 配对成功后命名设备，按用途申请短信角色/权限；来电权限在启用来电功能时再申请。
7. 列出检测到的 SIM，可命名“国内卡”“工作卡”。无法读取手机号时显示“号码未知”，允许手动填写标签，不能伪造号码。
8. 进入连通性验证：先确认心跳，再提示从另一手机向留守 SIM 发一条测试短信。界面模拟事件与真实短信测试必须区分。
9. 收件成功后展示“已准备就绪”。提供“配置通知”和“暂不开启”，两者均完成 onboarding。

失败与恢复：配对码过期可刷新；重复扫描给出已使用提示；部分权限未授权呈现“短信未就绪”而非整个设备“连接失败”；换后端前在 Android 确认数据将发往的新地址，旧队列不自动迁移。

## 流程 B：读短信与复制验证码

默认首页是短信列表。顶部显示当前筛选和简短设备异常条；正常时不让电量、信号图表占据主要空间。

每个会话行：发件人、最后一条摘要、SIM 标签、收到时间、未读状态。短信全文在登录后的详情中显示。识别到验证码可附“复制 381492”快捷操作，同时保留完整原文；多个候选时不替用户武断选择。

详情页：发件人 → SIM 标签 → 接收时间 → 正文 → 复制/回复。对字母发件人或明确不可回复对象不提供误导性的发送入口。复制成功显示短暂反馈；失败提供选择文本。

验证码识别只提供便利，不声称代码有效或必然正确。旧短信显示实际年龄；未获得有效期时不能显示精确“剩余 30 秒”。客户端展示本地时区，详情可查看完整时间。

进入详情才标记已读；预加载不标记。已读状态跨客户端同步。点击通知后若需要登录，登录后回到对应短信；已被删除则说明原因并返回列表。

## 流程 C：远程发短信

新建表单顺序：发送 SIM → 收件号码 → 正文。回复时固定原 SIM，切换需显式操作。按钮标明“使用 国内卡 发送”；多卡未选定时不允许提交。

号码支持国际格式；国家区号无法推断时要求补全。字符与预计分段数可显示，但不伪造运营商费用。首次启用发件时说明由实体 SIM 发送，可能产生运营商费用。

正常提交不增加无意义的二次确认；立即显示状态。按钮防连点与后端幂等同时存在。

| 内部事实 | 用户文案 | 可执行动作 |
| --- | --- | --- |
| 已存到服务器、未领取 | 等待手机处理 | 仅在尚未领取时尝试取消 |
| Android 已领取 | 正在发送 | 查看进度，不承诺可取消 |
| 系统发送回调成功 | 已发送 | 查看详情 |
| 收到送达报告 | 已送达 | 查看详情 |
| 已发送但没有送达报告 | 已发送 · 暂无送达报告 | 保持此状态，不倒推失败 |
| 明确失败且未发送 | 发送失败：具体原因 | 修复后重试 |
| 提交后无法确认结果 | 结果未确认，可能已发出 | 核对后主动重发，并提示重复风险 |
| 尚未执行即超过有效期 | 已过期，未发送 | 编辑后重新提交 |
| 部分分段已发送 | 部分发送成功 | 查看分段详情，不自动整条重发 |

设备离线时默认保留草稿。用户可明确选择“等待设备上线发送”，必须显示有效期（建议默认 5 分钟）；过期不再执行。PWA 无法连接后端时仅保留当前会话草稿，不做后台静默发送。

取消是服务器条件更新：如果设备已经领取，反馈“已开始处理，无法取消”，不能先显示取消成功再发送。

## 流程 D：通知配置

默认所有渠道关闭。通知配置分两层：渠道连接决定发到哪里，事件规则决定何时发、发哪些内容。首版使用简单表单，不做拖拽规则编辑器。

渠道卡片：名称、状态、目标摘要、启用开关、测试通知、最近一次投递结果。

- 此设备通知：检测是否支持、是否已安装、权限状态与订阅状态。在 iPhone 需要时展示添加主屏幕的指引。用户点击“开启通知”才请求权限。
- Telegram：引导创建 Bot、输入 Token、与 Bot 开始会话、绑定目标、发送测试。仅做出站通知，首版不通过 Telegram 执行发短信命令。
- 全部关闭：正常保存，说明“仍可在 SIMLink 查看短信”。不以红色警告呈现。

每个渠道设置内容级别：仅提醒（默认）、发件人、全文。选全文时展示真实格式的示例以及“短信正文会发送到该服务并可能出现在锁屏”的说明。

首版事件为新短信、设备失联；来电在能力开放后加入。默认继承全局规则，预留按 SIM 覆盖入口到后续。两个渠道都开启即同时发送，不暗示自动备用。

“测试请求已被服务接收”与“我已收到”分开呈现。失败展示原因、最近尝试和重试入口；网页通知被系统拒绝时引导去设置，不反复弹授权框。

延迟备用放后续：可以基于明确投递错误，或“指定时间内未打开短信”触发。设备接收 ACK 与用户打开不能混用，页面清楚说明可能收到两次提醒。

## 流程 E：设备状态与修复

设备页分开显示：服务端连接、最后心跳、短信权限、SIM 状态、最后同步、电量与充电。拿不到信号或电量显示“未知”，不能显示 0 或沿用旧值伪装实时。

“在线”仅说明近期联系过，不能代表 SIM 有信号或所有功能正常。示例文案：“手机在线，但短信权限已关闭”。

建议状态：正常、同步延迟、设备离线、需要处理。判定阈值在 P0 测试后确定。失联告警要抑制瞬时抖动，同一次故障只通知一次，恢复可给一条恢复提醒。

| 异常 | 页面反馈 | 下一步 |
| --- | --- | --- |
| PWA 无法连接服务端 | 当前无法刷新 | 检查当前网络并重试 |
| Android 未联系服务端 | 最后在线于 14:32 | 检查手机联网与运行状态 |
| 手机联网但 SIM 不可用 | 国内卡暂不可用 | 检查 SIM 与蜂窝信号 |
| 权限被撤销 | 需要在留守手机恢复短信权限 | 展示手机端操作路径 |
| SIM 映射改变 | 发送卡发生变化，待发任务已暂停 | 在手机确认卡片 |
| 通知失败 | 短信已保存，Telegram 通知失败 | 测试或修复渠道 |

Android 主屏只突出运行状态、服务器、SIM、待同步数量和修复操作。为了默认 SMS 角色而必需的本地短信功能必须可用，但不重复实现全部 PWA 管理功能。

## 页面清单与设计顺序

第一批：短信列表、短信详情/回复、新建短信、设备列表/详情、添加设备、通知设置、Android 连接与权限向导。

第二批：登录与首次管理员设置、数据/会话设置、来电记录（能力验证后）、通知投递详情。

每张页面在视觉稿中至少包含一个正常状态与一个关键异常状态。核心文案先定，再进行三个视觉方向探索，选择方向后实现交互原型。

## 可用性验收

- 新用户无需理解 WebSocket、VAPID 或 subscriptionId 即可完成配对。
- 登录后从列表找到并复制最新验证码，目标为不超过两次操作。
- 所有发件入口明确展示发送 SIM；不能因系统默认卡变化悄悄换卡。
- 不装 PWA、不授权通知、只用 Telegram、全部关闭通知四条路径均可完成短信阅读。
- 用户可区分“手机不在线”“SIM 不可用”“通知失败”和“发送结果未确认”。
- 状态不单靠颜色，控制具备可读标签和键盘焦点，移动端点击区域目标至少 44×44 CSS px，支持大字号与减少动画。
- 360px 宽手机和桌面双栏均不遮挡正文、主要按钮与异常提示；长号码、中文/英文正文、键盘弹起单独检查。

## 已选择的视觉语言

用户选择第一轮方案 1 的白底蓝色配色，结合方案 3 的 SIM 选择 tab。PWA 顶部保留“全部／国内卡／工作卡”，选中项以蓝色文字和下划线表达；下方“全部／未读”只过滤当前 SIM 范围。单张卡时简化选卡区，多张卡可横向滚动，不能压缩为难以点击的标签。切换卡片更新列表及发件上下文，已有草稿不悄悄换卡。

两端共用白色背景、深色正文、蓝色操作、绿色成功状态、细分割线和一致文案。用户选择的是视觉方向；精确颜色值、字号、间距仍需在 design tokens 阶段落实。

## Android 专属信息架构

采用“运行／短信／设置”三个入口，默认进入运行。首次没有配对时进入配置向导，完成后不再重复展示。返回应用时刷新状态，不能把旧成功状态当成实时结果。

运行首页按以下顺序呈现：

1. 当前最重要状态和修复动作：正常时显示“已连接 · 已接收的短信已同步”；有问题时显示具体问题及“去处理”。
2. 最近同步时间、待同步数量；“检查连接”只检查网络和 API，不宣称验证真实短信接收。
3. 设备名称、服务器地址、充电与电量。
4. 每张 SIM 的名称、卡槽、当前可检测的蜂窝状态与短信权限；未知即显示未知。未经过端到端验证不笼统宣称“短信可用”。
5. 默认短信角色、权限、后台运行设置。无法由应用检测的厂商设置显示“待手动检查”，用户自述完成标记为“已手动检查”。

运行页不突出暂停、解绑或更换服务器；这些放在设置内。顶部齿轮与底部设置在概念稿中重复，组件化时保留底部入口即可。电量等非可点击信息不显示误导性箭头。

## Android 配置向导页面与状态

| 页面 | 主操作 | 校验与恢复 |
| --- | --- | --- |
| 欢迎/连接服务器 | 扫码配对；手动输入为次操作 | 说明需要 Android 14+；相机拒绝仍可手输 |
| 确认服务器 | 显示实际域名，确认并测试连接 | 地址、TLS、API 错误分别解释，保留输入 |
| 设备配对 | 扫码令牌或输入配对码 | 码过期重新生成；未配对前不传短信 |
| 短信能力 | 设置默认短信应用，按需授权 | 每个权限解释用途，拒绝后保留进度，不循环弹窗 |
| SIM 配置 | 命名并选择启用哪些卡 | 无卡/卡未就绪显示原因，可保存为未完成状态 |
| 后台运行 | 查看当前设置并跳转系统设置 | 区分可检测状态与人工确认，不承诺永远在线 |
| 验证接收 | 引导从另一手机发送测试短信 | 同时显示手机接收和服务器同步结果；可稍后测试，首页保留待验证提示 |
| 完成 | 进入运行首页 | 显示已启用的能力和未完成项，不强制配置 PWA/Telegram 推送 |

向导显示简短进度，支持返回修改和中途退出；再次打开回到未完成步骤。扫码成功不能跳过服务器确认。换服务器时要求确认并重新配对，旧服务器积压的数据不自动发给新服务器。

## Android 异常与维护

| 情况 | 首页摘要 | 操作 |
| --- | --- | --- |
| 服务端暂不可达 | 无法连接服务器 · 3 条短信待同步 | 重试连接、查看网络诊断 |
| 短信角色/权限缺失 | 短信接收需要处理 | 前往对应系统设置 |
| SIM 被移除或改变 | 工作卡发生变化 · 待发任务已暂停 | 确认 SIM 映射 |
| 后台设置未检查 | 后台运行设置待检查 | 查看本机设置指引 |
| 凭证已撤销 | 设备已解绑 | 重新配对，不静默重建凭证 |
| 发件执行结果不确定 | 有一条短信发送结果未确认 | 查看本地记录，禁止自动重发 |

摘要按阻塞影响排序；成功不靠绿色表达，失败不靠红色表达。应用被系统强制停止时无法指望其自身显示即时异常；由服务端最后心跳辅助识别，下次打开 Android 时检查并恢复连接。

本地“短信”入口提供默认短信应用路线所需的阅读、详情、新建/回复和选卡能力，沿用 PWA 的列表及发送状态语义；具体系统角色职责在 P0 核实。它不是把 PWA 管理后台嵌进 WebView。

“设置”包含服务器与配对、SIM 名称、权限和后台指引、脱敏诊断、版本信息；通知渠道仍由 PWA 管理。更换服务器、解绑与清除本地数据采用针对后果的确认文案。

## Android 配置与恢复细化

以下三张是同一设计方向的不同页面，不是新的风格候选：

- [连接服务器](../design/vision/android-connect-server.png)
- [启用短信能力](../design/vision/android-sms-setup.png)
- [服务器断线恢复](../design/vision/android-connection-recovery.png)

为降低感知步骤数，向导将前述页面组织成四个阶段：连接（地址、确认、配对）、短信（角色、权限）、设备（SIM、后台设置）、验证（真实接收与同步、完成）。页内子步骤不改变阶段编号。

连接页：扫码为主入口，手动地址为备用入口。手动输入地址后点击“检查服务器”才发起连接；扫码解析后先显示地址并确认，再联网检测。检查中禁用重复提交、显示进度；修改地址使上次检测结果失效。API 兼容和 TLS 检查通过后进入配对，不能直接显示设备已添加。配对失效保留地址，仅重新输入令牌。手机键盘弹起时页面可滚动，输入和当前动作不被遮挡。

连接错误在输入附近呈现：“无法解析此地址”“服务器连接超时”“证书验证失败”“服务器版本不兼容”，保留输入。证书错误不提供忽略验证按钮。仅在必要时展开技术诊断，日志不得包含配对码或凭证。

权限页：当前任务只有一个主要按钮。角色请求或系统权限界面返回后重新读取真实状态，不把打开系统设置当作授权成功。若角色设置已经授予所需权限，直接标记完成，不重复弹窗；仍缺失时才请求对应权限。拒绝后给出影响说明与再次处理入口，不自动循环请求。图中连接成功状态仅在当次已验证时成立。

通知权限指 Android 本机运行提醒，与 PWA/Telegram 推送分开。可稍后处理；具体通知和后台行为由 P0 验证后确定，不暗示通知权限等同于后台运行权限。

“稍后设置/继续”保存非敏感进度，进入有明确“配置未完成”提示的运行页，展示下一项未完成操作，不显示正常运行。重新进入向导回到未完成阶段。未授权短信接收不显示“没有新短信”，应显示“尚未启用短信接收”。

恢复页：只有短信确已持久化到本地，才能显示“已接收的短信保存在本机”。存储失败采用另一种更高优先级错误。待同步数量来自本地队列，最后同步时间表示最近一次服务端确认，不是最近联网时间。

点击重试后按钮显示“正在连接”，防重复；连接成功但队列非空时显示“已连接 · 正在同步 3 条”，所有条目确认后才显示“已接收的短信已同步”。普通超时保留设备配对，不要求重新登录或重新配对。凭证撤销单独进入重新配对路径；过期发件命令恢复连接后仍不得执行。

“自动重试”显示调度器真实状态，不能在系统没有调度任务时声称等待重试。诊断先展示人类可读原因，导出前展示脱敏预览。生成稿的最近尝试、自动重试等只读行在组件实现时移除箭头；只有实际可进入详情的项目保留箭头。

设计验证清单：扫码拒绝→手动完成；地址修改→旧检测结果失效；角色已授予→跳过重复请求；权限拒绝→保存进度；断网→本地持久化→重连补传；连接恢复但未补完→不提前显示同步完成；400% 长文案/大字号下内容可滚动且主操作可达。

## Android 设备配置与验证页面

- [SIM 选择与命名](../design/vision/android-sim-setup.png)
- [后台运行设置](../design/vision/android-background-setup.png)
- [真实短信验证](../design/vision/android-sms-verification.png)

SIM 配置：开关决定该 SIM 是否参与远程同步，默认状态为待用户确认，图中两个开启状态代表已选择的示例。保存前不因检测到新卡而自动上传。首次只同步启用后收到的新短信，历史导入独立提供。关闭同步不关闭实体 SIM、不删除本地或服务端历史；已有待同步项目暂停上传，重新开启前说明积压内容的处理。首次全关允许保存，但运行页显示“未启用任何 SIM”。更换卡片暂停受影响的同步与发件任务，不能仅凭卡槽沿用授权。

卡名为空使用“SIM 1”等默认名称；限制建议为 20 个用户可见字符，保留 Unicode。重复名称给出提示，列表仍附设备/卡槽以便区分。手机号未知不阻止配置，手动备注的号码标为“手动填写”，不能当作系统验证。保存时再次核对卡映射；若已变化，保留名字输入并要求重新选择。

后台设置：系统可检测的电池状态与厂商人工检查分开存储。跳转系统页面失败时提供应用详情页或手动路径；返回后重新检测，不把点击按钮算作完成。人工勾选只改为“已手动检查”，不显示“后台稳定”。勾选可撤回，不强制勾选才能继续；未知机型提供通用说明，不猜测专用开关。详情中可记录检查时间。

短信验证：每张已启用的 SIM 独立创建测试会话及非敏感随机测试标识，图中 SIMLINK 7K2M 仅为示例。标识绑定设备、SIM 和本次会话；只匹配会话开始后收到的完整测试内容，忽略重复事件，旧短信不能让测试通过。重新开始生成新标识，切卡不把前一张卡的成功沿用。验证页不自动发出计费短信，引导用户用另一部手机发送；实际费用按发送方资费。

验证状态依次为：等待短信 → 手机已收到 → 等待服务器确认 → 接收与同步已验证。服务端持久化 ACK 必须对应同一事件；HTTP 连接成功不等于测试完成。此处不验证 PWA 阅读、通知投递、远程发件或长期后台运行。另设锁屏测试指引，不让前台单次测试替代持续运行测试。

等待约 2 分钟后显示“暂未收到测试短信”，提供检查收件号码/所选卡和继续等待，不宣布蜂窝接收一定失败。收到但同步失败时显示“手机已收到，尚未同步”并链接连接诊断。离开页面保留当前验证状态和时间；过程被中断后重新读取事件，不靠界面倒计时推断结果。

当前卡成功后显示明确文字“国内卡接收与同步已验证”，主动作变为“验证下一张卡”；所有已启用卡均成功后主动作变为“完成设置”。用户可随时查看运行状态或稍后验证，未完成的卡保留“未验证”标签。完成页展示成功范围、尚未完成事项及进入运行首页的按钮，不夸大为所有功能正常。

补充验收：全关/单卡/双卡；号码未知；保存时拔卡；两卡同名；后台设置无法跳转；取消手动检查；短信发到错误卡；旧测试消息补传；已收但服务器无确认；离开后返回；一张卡成功另一张未验证。所有设计图仍为静态稿，以上流程尚未经过真实设备测试。

## PWA 收件箱核心交互细化

- [会话详情与回复](../design/vision/pwa-conversation-reply.png)
- [新建短信](../design/vision/pwa-compose-sms.png)
- [留守手机离线的收件箱](../design/vision/pwa-inbox-gateway-offline.png)

详情页使用发件人和 SIM 作为会话上下文；同一号码不同卡的消息不能混入同一会话。消息按实际事件时间排列，保留同步时间供详情查看。长正文自然换行，号码可复制；链接不自动打开。验证码消息提供复制候选按钮，原文始终可展开查看；多个候选分别显示，不能复制不确定的拼接数字。字母发件人等不可回复对象不显示活跃回复框，改为“此发件人不支持回复”。本轮图展示的是可回复号码的会话，验证码只读详情尚待出图。

回复编辑器标明发送卡；切换卡进入该号码在另一张卡上的会话或新建表单，保留草稿但不伪造跨卡历史。更多菜单中的换卡动作必须同步更新标题、发件标签与提交目标。键盘弹起时编辑器保持可见，历史区缩小并可滚动；加载更早消息不打断当前阅读位置。返回列表恢复筛选和滚动位置。

新建页允许从当前选中卡预填；从“全部”进入且存在多卡时必须先明确选卡，不默默选择系统默认卡。只有一张可用卡时直接显示其名称。选卡 tab 不提供“全部”。国际区号与号码粘贴兼容，已含区号时不重复添加；本地区号无法确定时由用户填写。号码/正文错误在字段附近说明，提交前不跳出多余确认框。图中常驻“已连接不代表一定能够发送短信”文案在实现中移入状态说明，正常路径保持简洁。

提交按钮防连点；请求超时后按原幂等键查询命令状态，不能直接新建另一条命令。收到服务端受理后进入对应会话并显示“等待手机处理”，保留草稿直到确认已受理。最终“已发送”来自 Android 发送回调，“已送达”来自送达报告；未获取报告时不使用双勾或已读标记。

| 收件箱状态 | 用户文案/内容 | 主操作 |
| --- | --- | --- |
| 未连接任何设备 | 连接 Android 后，短信会显示在这里 | 添加设备 |
| 已连接但从未收到短信 | 还没有短信 | 查看接收测试说明 |
| 当前卡没有短信 | 工作卡还没有短信 | 切换 SIM |
| 未读筛选为空 | 没有未读短信 | 查看全部 |
| 网关离线、后端可达 | 已同步短信仍可查看，显示最后在线与最后同步 | 查看设备 |
| 网关已连接但积压 | 正在同步，保留历史列表与真实进度 | 查看设备详情 |
| PWA 无法连接后端 | 无法刷新，已加载内容可能不是最新 | 重试连接 |
| 登录失效 | 会话已过期 | 登录后返回原页面 |

网关离线仍可阅读后端已有短信；不等于 PWA 持久离线缓存。PWA 离线时只保留当前内存已加载内容，不写短信正文到 Service Worker 缓存。最后在线和最后同步属于不同时间，不能因网页刚刚刷新就显示“刚刚同步”。同一离线设备下所有卡都受影响；多设备场景只标记关联卡。

离线状态下“新建”仍可写草稿，提交区域明确“手机离线，尚未发送”。默认不排队；只有用户主动选择等待上线发送，并确认有效期，才创建待发命令。发送结果未确认呈现“可能已发出”，允许查看详情，主动重发前提示可能重复；明确失败、部分发送与未确认不能使用同一种重试动作。

草稿首版仅保留当前会话内存，离开编辑页后可在同一应用会话恢复；刷新/关闭可能丢失，应在确有草稿且用户离开时说明。若以后引入持久草稿，需单独设计设备隐私和清理机制，不以“自动保存”暗示当前已有持久化。

本轮检查覆盖：跨卡回复、长号码/长正文、键盘遮挡、字母发件人、多个验证码、重复提交、请求超时、网关与 PWA 分别离线、筛选空态。当前仅静态设计与规则检查，尚未实现或做真实交互测试。

- [验证码只读详情](../design/vision/pwa-otp-detail.png)
- [发送结果未确认](../design/vision/pwa-send-result-unknown.png)
- [桌面双栏收件箱](../design/vision/pwa-desktop-inbox.png)

验证码详情：识别出的验证码与原文同时存在，主按钮只复制选定的代码。复制成功以“已复制”短暂反馈，不遮挡正文；失败时允许选择文本。当前示例只有一个候选码，多个候选时分别标记其上下文，不任意选中。无可靠有效期信息不显示倒计时或“有效”徽章。字母发件人示例 DBS 不提供回复入口；普通号码短信即便识别到验证码，也按真实可回复能力决定是否呈现回复入口。

发送详情以原命令记录为依据，时间轴只显示已经观察到的事实；“手机已领取”本身不代表已调用短信发送接口。当前未确认示例摘要中的“已开始处理”在实现时应根据已上报的实际执行阶段决定，证据仅到领取时用“手机已领取任务，但尚未返回最终结果”。设备时间与服务端时间应保存来源并处理偏差，不能为使时间轴美观而伪造事件时间。

刷新状态只查询原命令，不发起新的蜂窝发送。重新发送是次级操作，打开确认层，明确展示号码、SIM、正文和“原短信可能已发出，再次发送可能重复”；确认后创建新命令并关联原记录。用户等待确认期间若原任务变为已发送或已送达，立即更新提示并要求重新审视，不能继续使用过时的失败状态。

| 发送详情状态 | 主操作 | 文案与边界 |
| --- | --- | --- |
| 明确未发送、权限缺失 | 查看设备 | 修复后由用户发起新的发送 |
| 待领取且未过期 | 查看进度 | 可请求取消，以服务端条件更新结果为准 |
| 未领取即过期 | 编辑后发送 | 明确旧任务不会再执行 |
| 已领取但结果未知 | 刷新状态 | 不自动重发，不显示“发送失败” |
| 多段部分成功 | 查看分段结果 | 不一键自动重发整条短信 |
| 已发送、无送达报告 | 返回会话 | 不将未获取报告解释为失败 |

桌面端在固定导航旁显示会话列表与详情两个业务栏。建议 ≥1100px 使用约 192px 导航、360–400px 列表和弹性详情；800–1099px 缩为窄导航，保证列表与详情各有足够宽度；不足时切换单栏路由。实际断点由文字放大、长号码和键盘测试校正。消息正文最大阅读宽度约 560px，不能随大屏无限拉长。

列表与详情独立滚动；回复编辑器固定在详情底部。列表选择由背景/焦点样式表达，未读由独立标记表达。生成图中当前已打开会话仍有蓝色未读点，落地时应在详情真正可见且标记已读后消失，不能永久保留。预加载和窗口后台状态不直接标记已读。

切换 SIM 后，若当前会话不属于新范围，详情回到“选择一条会话”，不自动跳进其他短信并标为已读。切换前保留当前应用会话的草稿；草稿携带原号码和原 SIM。点击新建在右侧展示新建表单，保留左侧列表；首次未选择会话时显示简短空态，不加营销插图或统计卡片。

使用正常 Tab 焦点顺序和可读控件名称，列表项可通过键盘打开；不提供单按 Enter 就发送的默认行为，Enter 在正文中换行。若后续增加发送快捷键，必须明示且能关闭。桌面详情 URL 可直接打开，浏览器后退恢复前一会话或筛选；手机与桌面共享消息、草稿上下文和发送状态规则，草稿尚不跨设备同步。

设计覆盖检查：单/多验证码、复制失败、不可回复发件人、状态查询与新发送分离、部分分段成功、确认期间状态改变、已读标记、跨卡切换、无选中会话、缩窄与放大文字。本轮仍为静态方向稿及规格，不声称交互测试通过。

## PWA 持久登录（用户已确认）

目标体验：在自己的设备首次登录后，从 iOS 主屏幕再次打开直接进入收件箱或通知对应的短信。关闭窗口、系统回收进程、手机重启、普通应用升级均不作为主动退出原因。持久登录为默认，不要求用户每次勾选“记住我”。

建议第一版采用同源部署、服务端不透明会话、持久 Cookie；不为此引入必须持续后台运行的机制。Cookie 使用 Secure、HttpOnly、Path=/、SameSite=Lax、显式 Max-Age，不设 Domain（可使用 __Host- 前缀）；服务端保存会话凭证摘要、过期时间、撤销状态和最近使用时间，数据库持久化。写操作同时校验 CSRF/Origin，所有私有接口仍做认证和授权，不把持有前端页面当作登录依据。

初始建议为 90 天不活跃过期，前台恢复应用并完成有效认证时续期；续期可限频，例如每天一次，同时更新服务端期限和 Cookie。单纯推送、心跳或后台轮询不延长不活跃期限。此时长是可调整的设计默认值，常用设备不会因固定每月到期被打断；清理站点数据、会话被撤销、长期不使用或凭证重置仍可能需要重新登录。不要把“默认保持登录”宣传成绝不会退出。

启动先进入简短的会话恢复状态，不先闪现登录表单；有效则直接进入目标页面。网络故障/服务器暂不可达显示重试并保留凭证，只有明确认证失效才进入登录页。403 权限不足与 401 登录失效分开处理。恢复中不展示未授权的短信正文；回到前台后重新确认服务端会话，设备被撤销时关闭私有实时连接并清理页面中的敏感内容。

会话管理以“浏览器/PWA 安装会话”为单位，不用设备指纹代替凭证。用户可给会话命名，查看最近使用时间、退出当前会话或撤销其他会话。复制安装 Cookie 可能使 Safari 与主屏幕 PWA 初始共享一个会话，不能承诺一台物理设备必然对应一个独立会话；撤销时文案说明关联会话也可能退出。撤销网页会话不撤销 Android 网关凭证。

退出登录必须服务端撤销会话、清除 Cookie 和当前敏感内存；后台静默续期不能把已退出的用户重新登录。关联通知订阅停止投递账户内容，重新登录后再明确绑定，避免共享设备退出后仍收到全文通知。账号密码重置时撤销网页会话并要求重新登录。无需每次打开 PWA 要求密码或生物识别；未来若加应用锁，作为独立的可选功能设计。

iOS 边界：WebKit 的 Safari 17.2 说明添加到主屏幕时会复制 Cookie（含登录状态），此后不持续共享网站数据。因此可以优化“先网页登录→添加主屏幕”的体验，但不依赖 Safari 与 PWA 登录状态永远联动；较旧系统或数据丢失时允许一次性补登录。Cookie 被平台清理不在应用可绝对控制范围内。

登录页文案建议为“登录后将在此设备保持登录”，不展示默认未选的记住我复选框。会话失效页说明实际原因并保留返回地址；仅接受站内返回路径。登录成功恢复阅读位置，但不得自动提交先前未发送的草稿。持久登录与短信正文持久缓存是两件事，现有不缓存短信 API 正文的默认规则继续生效。

验收：关闭重开、系统回收、重启手机、PWA 更新、后端重启、隔数日再打开、通知深链、Safari 安装到主屏幕、短时断网不退出、90 天不活跃后登录、另一会话撤销、退出后停止通知与私有连接。该体验尚未实现，需真实 iOS 主屏幕 PWA 验证。

依据：[WebKit Safari 17.2](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/)；[MDN Set-Cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)。

首次登录只展示品牌、当前站点域名、账号、密码和主按钮，不泄露短信、SIM 标签、设备名或设备数量。支持密码管理器的 username/current-password 自动填充、粘贴与密码显隐；字段标签始终可见，不只依赖占位符。提交中阻止重复请求，认证失败统一显示“账号或密码不正确”，保留账号并允许修改密码；网络错误单独显示，不能伪装密码错误。限速按服务端返回的等待时间呈现，不能自己猜测倒计时。

没有公开注册入口。“无法登录？”展开部署者密码恢复说明，引导在自己的服务器使用维护命令（实际命令待后端实现确定），不引入尚未实现的邮件找回。首次管理员初始化是独立的一次性部署流程，不把普通登录页变成任何人可认领的注册页。

正常启动不刻意停留在恢复画面。应用先显示静态外壳并检查会话；很快成功则直接进入站内目标，较慢时才显示“正在连接”。超时或离线呈现本轮连接失败页，“重试连接”重新验证原会话，不请求用户重复输入密码。生成稿的“已保留本机登录凭证”在实现中改成“本次连接失败不会清除登录状态”，因为 JavaScript 无法据此断言 HttpOnly Cookie 仍存在或有效。

明确收到认证失效后，复用登录表单并在上方显示原因：“登录已过期，请重新登录”或“此会话已退出，请重新登录”。只在成功认证后恢复原短信链接；返回路径只允许本站。待发送草稿不自动提交。403 权限问题不走重新登录循环。续期与退出并发时，以服务端撤销结果为准。

登录设备页中的名称为用户命名或保守的平台描述，不冒充硬件唯一身份；“最近使用”标识应用前台有效访问，不能根据后台轮询伪装活跃。此会话置顶，其他按最近使用排序；重命名不改凭证。无其他会话时显示“没有其他登录会话”，隐藏批量退出按钮。

单个“退出”需要展示具体会话名称及后果的确认层；批量退出说明保留当前会话，并列出将退出的数量。服务端撤销成功后才从列表移除；请求超时先刷新核对，不显示假成功。撤销不会删除短信，不影响 Android 配对。对于可能共享同一初始会话的浏览器/主屏幕安装，确认文案说明关联窗口也会退出。

主动退出当前会话成功后清除本机敏感内存和 Cookie，返回登录页，停止关联账户通知。网络失败时不声称服务端已撤销；隐藏当前敏感内容，提示“退出尚未完成，请联网后重试”，保留退出意图，恢复网络后先完成退出而不是自动回到收件箱。不能用 JavaScript 清空内存来冒充 HttpOnly Cookie 已清除。具体退出与恢复并发行为须随后端实现验证。

后续测试：密码管理器、显示密码的读屏标签、弱网启动不闪登录、过期与离线区分、刷新/退出并发、深链恢复、撤销失败回滚、批量退出保留当前会话。当前交付为静态设计稿与状态规格，尚未实现认证。
