# SIM 清单、号码与消息归属

## 当前实现

Android 0.3.0-p1 使用已有 READ_PHONE_STATE 权限读取当前可见订阅，随同步任务上报订阅编号、卡槽与运营商。无权限、读取失败、有效空清单分别表达，不将读取失败当作拔卡。无新增读取号码权限，不采集 ICCID、IMSI 或系统电话号码。

Web「设备」中可为每个映射填写备注名及可选电话号码。电话号码移除空格、括号和连字符后保存，允许可选 `+` 与 6–20 位数字；建议填写国家/地区代码。号码是用户确认的区分信息，不是运营商验证的身份，不用作数据库主键。名称与号码都会显示在收件箱 SIM 标签及消息归属处。修改后下一次前台刷新生效。

## 映射规则

- Android 为观察到的订阅编号、卡槽、运营商组合分配随机 UUID，SQLite 持久保存；相同观察值保留编号。
- 观察到移除后再插入，或订阅编号/卡槽/运营商变化，创建新编号。不自动继承旧名称、号码或历史会话，不仅凭相同号码合并消息。
- 后端以设备 ID + 映射 UUID 隔离数据。两个设备即使填写相同号码仍保持独立；重新配对创建新的设备身份。
- 收件时将可确定的映射 UUID 写入持久 outbox；断网后换卡、补传、重试不会重新按当前卡分配旧短信。读取映射失败仍保存短信，归属保持未知。
- 升级前短信与 outbox 不回填映射；无可靠信息时显示订阅编号与“未关联卡片”，不猜测历史属于当前卡。解绑保留短信、历史映射名称和号码，设备条目移除。

普通应用只能识别可观察到的映射变化，不能可靠证明永久物理卡身份；未被观察到且所有字段相同的更换无法检测。运营商显示名称变化也可能产生新映射。因此未来远程发送必须在执行时检查当前映射、权限与用户确认，不能仅凭电话号码或这个清单自动发送。

## 升级与兼容

后端 SQLite v3 增加 sims、设备清单状态及 messages.sim_key；Android 数据库 v3 增加本地映射及 outbox.sim_key。先备份，再升级后端，最后升级 Android；旧 Android 可继续发送不带 simKey 的短信。新 Android 遇到不支持清单接口的后端时，带映射的新事件保留队列重试，避免降级改写事件归属；旧的无映射队列仍可上传。Web 与 API 同镜像部署。

清单不是实时卡可用性承诺。Web 展示最后上报时间，“最近上报在用”与设备是否在线分开表达。观察到有效空清单会退休当前映射，后续再次出现需重新命名；暂时读取失败则保留本地映射。

## 验证

自动化覆盖映射稳定、移除再出现、卡槽/订阅变化、双卡列表换序、改名/号码归一化、CSRF、事务回滚、重复上传归属冲突、解绑后历史保留和容器重建后号码持久化。浏览器用虚构号码验证设备页编辑与收件箱标签同步；390px 布局未发生横向溢出。真实换卡、双卡与本轮新版短信归属仍需真机验收。
