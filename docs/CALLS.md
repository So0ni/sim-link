# 新来电同步

2026-10-02：首版已实现，模拟器验收见 [来电验收](CALLS-ACCEPTANCE.md)。已部署正式与测试环境，并覆盖安装 Android 16 真机；真实来电与后台可靠性仍待验收。

## 范围与行为

Android 设置 → 来电同步，先正常授权 READ_CALL_LOG / READ_PHONE_STATE，再显式启用；默认关闭且绑定当前配对 generation。权限拒绝不影响短信。只采集本次启用之后开始的入站电话，不导入此前历史；重新启用建立新起点，原配对已经采集的待上传事件继续发送。关闭停止后续采集与上传，已有本地/服务端副本保留；关闭时已经发出的网络请求可能完成。

只处理系统给出的 incoming / missed / rejected / blocked，忽略 outgoing、voicemail 和未知类型；不根据时长为零推断未接。号码受隐藏/限制时上传 null。首版所有来电 simKey 为 null：电话账户 ID 不是 subscriptionId，未验证映射前显示“SIM 未知”。不接管默认拨号角色、不访问通讯录、不接听、不远程拨号。

Web 增加「来电」导航，沿用白蓝、下划线筛选、移动详情与宽屏双栏。列表按来电原始时间倒序，API 每页 100 条，支持“更早记录”。SIM 标签使用单行高度；「全部 / 未接」为独立状态按钮，与 SIM 筛选取交集，未接数量按当前 SIM 范围统计。筛选对已加载记录生效。查看详情自动写入 viewedAt，单向已查看；这不改变系统通话结果，也不表示用户已经回拨。号码支持复制及 tel 链接交给当前设备拨号器确认。来电数据仅留在页面内存，不新增持久浏览器缓存。

已订阅 Web Push 的浏览器默认收到新未接来电提醒，标题不含号码，点击直达对应记录。超过一小时的来电只入库，不逐条补推；首版不发离线汇总通知。已接/拒接/拦截只记录，不推送。沿用现有通知开关和会话归属，来电不计入现有短信未读角标。

## Android 分工

- `calls/CallCollector`：读取系统记录，无网络；ID 升序每批最多 100 条，加最近 100 条有限回查。使用 CallLog URI 的 limit 参数，不向排序表达式拼 LIMIT。
- `calls/CallPolicy`：系统类型映射与 Provider 重置游标策略，纯 JVM 可测。
- `calls/CallStore`：独立来电表、启用起点、采集进度、事件 ID、队列状态。新事件和采集游标同事务提交；本地成功与服务端 ACK 分离。`generation + source_id + started_at` 去重，首次生成不可变 UUID，重复观察不重复安排上传。
- `calls/CallCaptureScheduler`：无网络要求的持久 Job 105；IDLE 广播安排延迟约 2 秒检查并保留最多三轮检查意图（系统退避可延后）。应用启动、现有完整同步和心跳唤醒也触发独立本地执行器补查，不占短信 LocalIo，不等待网络。
- `calls/CallSync`：在现有 SyncRunGate 内通过同一设备凭证上传，匹配 ACK 后才完成；400/409 隔离单事件，可在权限/服务器/手机时间问题修正后主动“重试需处理记录”，网络错误保留队列，401/403 暂停连接，404 提示升级服务器且不阻塞短信。
- `sync`：已有任务 103 由短信专用改为共用 incoming-event 加急任务，拒绝后普通任务兜底，保留原任务 ID。`IncomingSyncDispatch` 保留执行期间的新请求。来电积压时一轮先处理最多 8 条短信，再最多 10 条来电；无来电时保留 40 条短信预算。仍受原心跳 8 秒总窗口限制，不为来电延长唤醒锁或添加闹钟。
- `ui/CallSettingsPage`：使用已有 GatewayStyle 展示权限、开关、最近成功检查、待上传/阻塞数量；界面定期刷新，心跳成功不代替来电成功。

系统记录可能晚于 IDLE 广播生成，重复广播仅触发检查，不创建业务记录。晚插入的长通话按记录 ID 扫描，不使用“上次扫描时间”过滤。Provider 重置时回退游标，有限回查覆盖近期 ID 重用。系统删除的未采集记录、关机/无服务未形成的记录、启用前已开始的通话不保证可恢复。手机时间大幅调整、超出有限回查范围的原记录后续修改不是首版强保证。

## 服务端与兼容

后端 `modules/calls/service.mjs` 拥有事务、去重、读取和状态上报，`routes.mjs` 只处理 schema 与认证。SQLite v12 追加 calls/call_status，保留原短信、身份、会话和推送数据。Android 本地 SQLite v6 追加 call_settings/call_events，不改变短信表。

先升级后端/Web，再升级 APK。旧 Android 不上传来电，界面显示“尚未上报”；新版 Android 遇旧服务端来电接口 404 保留队列，短信继续。发现文档公开能力 `calls.receive.v1`。协议见 [API v1](API-V1.md)。设备撤销后不能上传；历史来电与短信一样保留。没有新增清理/删除接口，备份包含号码及记录，按已有私有数据备份规则处理。
