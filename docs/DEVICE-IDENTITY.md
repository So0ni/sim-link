# 安装身份与连接生命周期

## 身份边界

- installationId：Android 首次创建数据库时生成随机 UUID，升级、重启、解绑不改变；卸载或清除应用数据后重新生成。不读取 IMEI，不随备份迁移。
- serverId：后端 SQLite v4 生成并持久保存，换 IP、域名或重建容器不改变；全新数据库有新的 serverId。它用于判断数据归属，不是认证秘密或证书。
- deviceId：后端设备记录 ID，关联短信、SIM 映射及号码备注。管理员恢复绑定保留这个 ID。
- deviceToken：随机设备凭证，服务器只保存摘要；恢复绑定成功后轮换。installationId 本身不能授权接管设备。

## 更改同一后端的地址

Android「服务器与同步 → 修改服务器地址（保留配对）」输入新 origin，HTTP Debug 仍需明确允许。提交前展示目标地址并确认会向其发送现有凭证；已知 serverId 不匹配时，在发送凭证前停止。公开 serverId 不能证明服务器可信，仍依赖用户确认地址及 HTTPS 系统证书验证，不绕过 TLS。

新地址通过已有 token、deviceId 和 installationId 验证后，本地重新加密地址相关的凭证 AAD，原子更新 origin/serverId，保留 generation、token 与 outbox。验证失败不替换原连接，不自动创建新设备。网络操作与同步共用串行 NetworkIo，避免迁移时旧任务继续上传。

旧版本已有连接没有 installationId 绑定时，新版通过有效 token 首次登记，不要求重新扫码；同一设备不能被另一 installationId 覆盖。后台首次成功联系也会完成这个登记。

## 恢复绑定

Web 管理员在指定设备旁点击「恢复绑定二维码」，确认后生成绑定该 deviceId 的五分钟一次性邀请。已知 installationId 用普通“添加设备”二维码配对会返回 409，不创建重复记录；必须使用管理员指定的恢复邀请。

恢复邀请只能由原 installationId 消费；尚未登记安装身份的旧设备可通过管理员针对该设备的邀请完成首次登记。配对消费、身份检查和 token 轮换在同一事务内完成；失败不消费邀请。成功后撤销旧 token 及该设备其他未消费的恢复邀请，保留设备名称、SIM 配置与短信。

Android 仅在本地已经知道 serverId 且服务端返回相同 serverId/deviceId 时保留原 generation；跨后端或无法确认历史身份时不重新绑定旧队列。明确解绑后本地旧 generation 已移除，恢复不会自动重启那些历史队列。

解绑仍移除有效设备与凭证。单独保留 installations 中的安装 ID、设备 ID 和名称，Web 默认折叠的「恢复已解除配对的设备」可生成恢复邀请；它不在正常设备列表中，也没有访问权限。没有安装登记的旧设备在删除后无法据安装 ID 自动恢复，不猜测或合并历史设备。

## 兼容与失败恢复

后端 v4 兼容旧 Android 配对请求。新版身份/恢复功能需要先升级后端；旧后端没有身份能力时既有收件仍可运行。新安装配对携带 installationId，需要新版后端。升级前备份，同一数据库保留 serverId；不要将两个独立运行的服务端副本当作一个实例。

扫码响应丢失可能已经完成 token 轮换。此时通过原设备的恢复邀请再次配对；不按安装 ID 静默签发凭证。清除应用数据后属于新的安装，不自动接管原安装。
