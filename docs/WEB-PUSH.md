# Web Push 新短信通知

> 公开记录已省略私人部署地址；验证范围和结果保持原记录。

2026-09-29 首版实现；范围为新短信、此浏览器安装实例，暂不包含 Telegram、设备失联或正文通知。依据用户最新决定，通知包含发件人，不显示短信正文。真实 iPhone 系统通知验收仍待完成。

通知标题使用“xxxx 发来一条短信”，正文默认留空，可在「此设备通知」选择预览前 50、100 或 200 个字符，超长加省略号，按完整可见字符截断并合并连续空白。无法校验会话时使用“新通知”标题及“打开 SIMLink 查看新通知”提示，不显示发件人或正文。旧 Worker 在更新前仍采用旧样式。

正文预览增量（2026-09-30 已部署正式和测试环境）：SQLite v11 为每个推送订阅保存 previewLength，旧订阅和新订阅均默认 0（关闭）；重新登录绑定后恢复默认关闭。投递时读取当前设置和原短信，新增可选 preview 字段，不重复保存正文到通知任务或诊断历史。关闭后尚未投递的任务不再附正文，已受理的推送无法撤回。旧 Worker 忽略 preview，新 Worker 兼容没有该字段的服务端。测试通知不携带短信预览。此增量覆盖首版不提供正文预览的限制。两环境升级前均保留数据及配置备份，数据库完整性和推送身份校验通过，真实 iOS 展示待复测。

## 使用与边界

- PWA 更新后，在「设置 → 此设备通知」点击「开启通知」，主动授权；默认关闭。每个浏览器/安装实例分别开启。
- iPhone 从 Safari 添加到主屏幕后，在主屏幕应用内操作。能力不足或权限关闭时展示恢复说明，不自动反复请求权限。
- 开启后可发送虚构测试通知。页面的“推送服务已接收”仅说明推送服务受理，不等于系统已显示或用户已读。
- 新短信提醒显示发件人；点击打开原设备、原 SIM、原发件人的会话。需要登录时保留 hash 路由，登录后继续访问。只有实际可见详情触发既有阅读状态逻辑。
- 关闭通知仍可读短信。服务端删除该订阅及待投递任务；退出、撤销或会话到期停止关联投递。重新登录后需明确开启，不自动重新绑定旧订阅。
- 已被推送服务接受或已显示的通知无法撤回。Worker 在显示发件人前检查当前会话；401 或不同会话不显示，网络不可用时仅显示无发件人通用提示，点击返回收件箱。
- 短信接收时间距服务器超过一小时的补传不提醒；不回溯订阅前历史。每个订阅、消息最多创建一项任务。

## 存储与投递

SQLite v7 增量迁移保留现有短信、阅读状态、设备及命令。VAPID 密钥首次启动生成并保存在同一数据库；不需要额外环境变量，不能在升级时重建密钥。备份包含密钥、浏览器 endpoint 和订阅密钥，按敏感凭证保护。

短信入库事务中写入通知 outbox；设备只等待本地事务提交，不等待外部推送。每 5 秒处理最多 20 项，单进程最多 4 路并发投递；每项请求配置 10 秒总截止取消信号（含连接与响应），发送 high urgency。保存尝试次数、最近尝试时间和结果（不保存外部错误正文）。网络错误、429、5xx 按 30 秒起指数退避、最高 15 分钟，最多 6 次，任务最多保留一小时投递窗口。404/410 删除失效订阅；其他明确错误停止自动重试，可在设置中发送测试通知。

进程崩溃后任务保留并重试；服务端受理但本地尚未记账时可能重复发送，使用稳定 notification tag 合并替换同消息提醒，不宣称 exactly-once。完成/失败/过期记录在 7 天后清理；短信保留规则不变。

endpoint 仅接受 HTTPS 默认端口、无用户信息/fragment，并限制为 FCM、Mozilla、Apple、Windows 的已知推送域名；不跟随任意用户提供的 HTTP 地址。新浏览器供应商需评估后扩展服务端白名单。通知数据使用标准 Web Push 加密，VAPID 私钥只在服务端；不记录 endpoint/密钥/短信正文。

## 接口

均为管理员网页会话接口；写操作校验 Origin 与 CSRF。Android 收件协议不变，已有 APK 不需要升级。

- `GET /api/v1/push`：VAPID 公钥、当前会话订阅 ID 及各自最近投递状态；不返回 endpoint 或订阅私钥。
- `POST /api/v1/push/lookup`，`{endpoint}`：仅查询当前会话绑定 ID，无匹配为 null。
- `POST /api/v1/push/subscriptions`，`{endpoint,keys:{p256dh,auth}}`：校验并绑定当前安装；相同订阅幂等，显式重新绑定清除旧会话任务。每会话每分钟 20 次，服务器最多 100 个订阅。
- `DELETE /api/v1/push/subscriptions/:id`：仅删除当前会话拥有的订阅。
- `POST /api/v1/push/subscriptions/:id/test`：排队测试通知，返回 `{queued:true}`；每会话每分钟最多 3 次。

状态：`pending`、`accepted`、`failed`、`expired`。`accepted` 不代表设备显示或用户已读。

## 验证

自动化覆盖：入库/outbox 事务与回滚、事件幂等、旧补传抑制、发件人且无正文、会话/CSRF/endpoint 校验、跨会话归属、退避/过期/失效订阅、退出清理、v6 迁移及密钥/任务重启持久化；Worker 覆盖会话校验、离线隐私回退和安全深链。

真实设备待验收：开启系统权限 → 发送测试通知 → 将 PWA 切到后台/锁屏 → 新虚构短信触发通知并显示发件人 → 点击回到对应会话 → 关闭/退出后不再接收新通知。自动化 mock 和浏览器页面验收不代替此项。

实现参考：[PushManager.subscribe](https://developer.mozilla.org/en-US/docs/Web/API/PushManager/subscribe)、[web-push](https://github.com/web-push-libs/web-push)。

## 2026-09-30 · 通知成批显示的待定位反馈

用户反馈手机系统通知有时直到下一次才两条一起弹出，尚未确认第一条短信入库及推送受理时间。当前代码由独立5秒定时器处理队列，没有等待下一条短信才能投递的条件；但串行投递可能受前一项慢请求影响。web-push的timeout配置是网络socket超时，不能作为端到端10秒显示保证。Worker显示通知前还会校验在线会话（配置10秒AbortSignal超时），所以推送服务已受理仍不能证明通知已显示。

定位时区分Android接收/上传、服务端通知pending/attempts/attemptedAt/result、推送服务accepted和手机实际显示。第一条未弹出时若前台PWA已能看到短信，可缩小到入库后的投递链路；若短信也未同步，应先检查Android队列。只有取得相应时间证据后才判断根因，本次没有宣称修复系统通知延迟，也没有移除隐私会话校验。


## 2026-09-30 · 延迟改进、阶段回报与角标

用户补充：PWA内已看到短信，点击测试推送后旧通知与测试通知一起出现。本轮实现上述并发/截止优化；Worker显示前的会话校验改为2秒取消预算（旧服务回退可额外2秒），慢网/离线继续只显示无发件人通用提示。系统暂停Worker时计时也可能延后，不承诺墙钟2秒显示，也没有直接证明此前问题根因。没有取消登录隐私校验，401/不同会话仍抑制旧通知。

Worker在push事件开始记录本地收到时间，校验通过后异步回报；showNotification完成后补报时间。回报不在显示的等待路径上，不重试通知本身；失败不生成额外通知。设置页保留最近10条，点击测试不会覆盖旧通知的诊断条目。时间/权限/兼容规则见API-V1。

支持Badging API的主屏幕PWA：登录前台从服务端summary读取全部未读数（约5秒、标读后唤醒），后台通知校验时读取同一总数；不按推送次数加一，不用已加载消息数。零未读、退出、明确401时清除；网络失败保留最后确认数，不猜零。离线推送不更新计数；其他设备标读后，后台角标可能到下一次前台恢复/推送才校准。不发送仅更新角标的静默推送，不以角标替代系统可见通知。iOS16.4+需要添加到主屏幕及通知权限，用户可单独关闭角标；实际iPhone表现待测。

本轮后端/Web未部署。需要部署v10后更新PWA，分别验收锁屏通知、慢网络通用通知、退出隐私、未读减数及其他端标读校准。若再次成批出现，查看旧通知acceptedAt与workerReceivedAt/notificationShownAt，缺失回报也可能是断网而不是未接收。
