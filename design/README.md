这是两端实现基线草案，沿用用户选定的白蓝配色与 SIM tab；尚未实现组件或交互原型。

用户明确要求优先，其次 UX 行为规格、组件规格与 tokens，最后是生成图片。图片用于视觉参照，不能推翻状态真实性、授权与发送语义。

## 核心设计决定

白底、深色正文、蓝色主操作；选卡使用蓝色下划线，列表优先采用留白和细分隔线。绿色只用于有证据的成功，琥珀用于待处理或结果不确定，红色用于明确错误与破坏性操作。状态必须有文字，不能只靠颜色。

当前只定义浅色主题。精确 token 值是本轮为实现选定的基线，不声称从生成图精确取样。生成图中的渐变蓝按钮统一为纯色，重复文案、无意义箭头与未读标记按组件规格清理。

PWA 和 Android 共享语义、色彩与尺寸节奏，各用原生控件行为；不共享运行时 UI 源码。Android 使用系统权限对话框和返回行为，Web 使用真实表单、链接和键盘焦点。无需为了图像一致性绘制假系统控件。

## 实施前组件验收目录

未来 Web playground / Android Preview catalog 至少覆盖：按钮全状态；字段错误与大字号；SIM 单卡/多卡/离线；短信未读/选中/长文本；发送所有结果；向导权限拒绝；会话恢复成功/网络失败/认证失效。使用明确标记的演示数据，不连接真实 SIM，不产生付费短信。

交互原型完成后再用 390px 手机、360px 窄屏和 1440px 桌面对照图检查，额外检查文字放大、键盘弹起及减少动画。静态 token 检查不能替代这些验证。
