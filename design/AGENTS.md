# 设计补充约定

适用于此目录，结合 [根约定](../AGENTS.md)。先读 [设计系统入口](README.md)，按任务读取 [UX](../docs/UX.md)、[组件规格](components/README.md) 和相关视觉稿。

## 已选方向与来源

保持白底、蓝色操作、深色正文，PWA 使用顶部 SIM tab。Android 共享视觉语言但以运行状态与配置为中心。不要因新增页面重新探索另一套品牌风格，除非用户要求。

产品行为以 UX 规格为准，组件结构与状态以组件规格为准，精确值以 [tokens.json](tokens/tokens.json) 为准，生成图片为视觉参考。未读点、只读行箭头、重复状态、渐变按钮和不准确文案按文档修正，不机械照搬图片错误。

## 修改规则

- tokens 是可机读参数的单一来源，当前为项目自定义 JSON 格式；不宣称兼容未接入的工具。
- 修改 token 需检查 Web/Android 映射与相关组件，更新用法和对比度报告；不单独手改未来生成的 CSS/Kotlin 文件造成漂移。
- 新组件描述用途、结构、状态、交互、平台差异和验收。按真实需求补充，不提前制造庞大组件库。
- 状态必须有文字依据：未知不显示成功，已发送不等于已送达，人工检查不等于系统验证。
- 原图保留，修改稿采用新文件名并更新索引；只把最终使用的工作区文件作为项目引用，避免依赖个人缓存绝对路径。
- 概念图、组件 demo、可点击原型与生产功能明确区分；示例数据虚构且不接真实短信发送。

## 验证

token 修改检查 JSON、类型/尺寸、预期色对比与引用链接。当前报告记录的是颜色组合计算，不是完整 UI 可访问性认证。更新报告时用实际新值重新计算，不手写“通过”。

UI 实现后检查手机 360/390px 与桌面 1440px、文字放大、键盘弹起、安全区、焦点、读屏标签和减少动画。常规文字对比内部目标至少 4.5:1，必要控件边界/焦点至少 3:1。不能以静态图或单次截图替代交互与真实平台验证。

当前尚无运行中的组件 catalog。创建后记录真实预览与检查命令，不编造 Storybook 或 Compose Preview 已存在。
